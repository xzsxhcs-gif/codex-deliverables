# 《微光归途》音乐结构独立复核

复核对象：`score.py` 与本次实际生成的 `notes.json`。这是代码／音符事件层面的乐理检查，**没有声称完成真人听审**；最终音量、声部存在性和释放尾音由音频验证另行确认。

## 结论

作品有明确的原创主题与五段曲式，配器和音域适合温柔、逐渐展开的电影感方向。643 个音符事件不是随机音符堆叠：随机种子只作用于轻微演奏差异，音高与时值均有具体设计。没有发现超出乐器合理音域或同一通道同音高重叠导致的截音问题。

初次复核发现的两处小和声问题已修正，并已重新检查最终 `score.py` 与新生成的 `notes.json`。当前没有发现需要继续纠正的明确乐理／事件问题；具体修正记录见下文。

## 曲式与主题

- 32 小节、4/4；开场4小节、发展8小节、推进8小节、高潮8小节、回归4小节。
- 基础速度90 BPM，最后4小节逐渐降至70 BPM；含0.3秒起始空间与3秒释放，总长约90.03秒。
- F#–A–D 的上行三度／四度，以及 `.5 / .5 / 1.5` 的节奏形成可辨认头部。
- 第1、3、5、8个主题小节通过相同头部、不同尾句形成呼应；较长休止集中在句末，保留呼吸。
- 推进段把主题迁移至小提琴，钢琴改为流动伴奏，长笛错位回答。高潮只对局部主题抬高音区，最高为D6，避免整段抬高八度造成刺耳。
- 回归段重新交给钢琴，并用 Gmaj9 → D/F# → Em7/A7 → Dadd9 收束；配器退出和减速支持自然结束。

## 已完成并复核的两处修正

### 1. 高潮第22小节的悬留音：已解决

初版中，该小节第2.5拍起的D5在A/C#上形成未解决悬留。最终版本已改为 **C#5**，保留原有节奏，形成 E5 → C#5 → 下一小节F#4 的清楚连接。

已在最终音符数据中确认该小节的对应事件为 MIDI 73（C#5），`start_beat` 约86.506、时值约0.994拍，没有继续保留原D5。

### 2. 高潮竖琴半小节换和声：已解决

初版竖琴只读取每小节第一个和弦。最终版本改为按每个事件的起拍查找当前实际和弦：

- 第26小节后半已使用 A7 材料，后续音包含 G4、C#5，而不是原先的晚到D4。
- 第27小节后半使用 E4、G4、C#5，随钢琴／圆号一起进入 A7。

已同时检查选取逻辑和导出的实际事件，未再发现上述未解决的半音冲突。半小节交界处的前一音尾声仍可自然重叠，这是正常的演奏释放，并不要求把所有声部机械切断。

## 听感与验证边界

最终代码中没有发现必须推翻曲式、主题或配器的理由。音符检查不能证明实际 SoundFont 的主旋律清晰度、混响距离或审美听感；应结合分轨RMS、完整波形、高潮／回归能量、末尾释放和削波验证。不能据此声称与世界上全部已有音乐都没有相似片段，只能确认本次明确写作而未复制项目示例曲。
